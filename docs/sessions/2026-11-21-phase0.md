### Decisions needed (options, pros/cons, recommendation)
1. **Profile validator.** (a) **pydantic** (placeholder): Python-native, cross-field rules, good errors, exports JSON Schema; (b) JSON Schema + `jsonschema`: language-neutral, but cross-field rules are awkward and error messages are poor; (c) both hand-written: they drift. **Recommend (a)**, with the exported schema used only for editor hints (a test keeps it in sync).
2. **PostGIS version.** (a) **17-3.6** (placeholder): widest managed-host support today; (b) 18-3.6: newest, async I/O, but not yet offered by every managed host; (c) 16-3.5: oldest still supported. **Recommend (a)** until the hosting provider is chosen, then match it exactly.
3. **Raw folder scheme (manual downloads now, Phase 2 later).** (a) **`data/raw/<source>/ingest_date=YYYY-MM-DD/`** (placeholder): Hive-style, so DuckDB, Spark and Snowflake prune by date without config; (b) `<source>/YYYY-MM-DD/`: shorter, but needs path parsing; (c) `<source>/YYYY/MM/DD/`: good for very high volume, overkill here. **Recommend (a).**
4. **Name map design.** (a) **One global alias table keyed by LGD code** (placeholder): simple, each alias explained by type and evidence; (b) per-source mapping `(source_id, raw_name) → code`: handles a name that means different things in different sources, but repeats the same aliases many times; (c) global table plus per-source overrides. **Recommend (a)**, moving to (c) only if a real collision appears.
5. **Spine and name map as committed seeds vs dbt models.** (a) Seeds now; in Phase 3 the spine becomes a staging model over `raw.lgd`, aliases and lineage stay seeds, and the name map becomes an intermediate model; (b) keep everything as seeds forever: simple, but LGD updates need a manual notebook run. **Recommend (a).**
6. **Notebook outputs in git.** (a) **Keep** (placeholder): GitHub shows the evidence, which helps the portfolio; (b) strip with nbstripout: clean diffs, no data in git. **Recommend (a)** for EDA notebooks while outputs stay small and public.
7. **LGD PDF committed as a test fixture (25 KB).** (a) **Keep** (placeholder): a real-world parser test; (b) replace with a synthetic PDF before going public. **Recommend (a)** if the LGD licence allows redistribution (see licence item below), else (b).
8. **Size class: derived or declared?** (a) **Derived** from plot acres at a given TPD (placeholder): can't contradict the land rule; (b) declared in the profile: a target class, but can disagree with the TPD range. **Recommend (a).**
9. **camelot.** Not installed: pdfplumber handled LGD. **Recommend** adding it only when a ruled ("lattice") table defeats pdfplumber.
10. **Fuzzy matching library.** (a) **stdlib `difflib`** (placeholder, suggestions only); (b) `rapidfuzz`: faster, better scorers. **Recommend (a)** until a source has many unmatched names.

### Data findings (EDA only): coverage, surprises, licence issues
- LGD: **75 districts**, codes unique; 70 in 118–187, five later codes: Kasganj 633, Amethi 640, Sambhal 659, Shamli 660, Hapur 661.
- **Not in Census 2011:** Amethi, Hapur, Sambhal, Shamli. **Not in Census 2001:** those plus Kasganj. Census-based variables will need a parent-district proxy (DQ-003, high).
- Etah's Census 2011 code (201) is out of sequence, as is Kasganj's (202), so Census 2001↔2011 codes aren't positional (DQ-004).
- LGD's "local language" column is upper-case English, not Hindi; Mirzapur's value is 9 NUL bytes, which Postgres would reject (DQ-001/002). Phase 2 loaders must strip control characters.
- LGD short codes keep old names (FZB, ALB, SRD): evidence for three renames.
- pdfplumber's default table finder silently drops every white row of the zebra-striped LGD PDF (≈half the data). Fixed in the parser; a good interview story.
- **Licence:** LGD terms not yet found. Needed before the repo goes public (fixture + seeds contain LGD data).
